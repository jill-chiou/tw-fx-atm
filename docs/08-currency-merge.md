# 幣別資料 Merge 規則

> 建立日期：2026-05-09
> 目的：記錄如何將各銀行官網爬取的幣別資料，合併回 FISC 位置資料（`atm_geocoded.json`）。

---

## 背景

FISC PDF 提供所有外幣 ATM 的位置（銀行名稱、裝設地點、地址），但**不含幣別**。
各銀行官網有幣別資訊，但格式各異、完整度不一。

目標是：為 `atm_geocoded.json` 中每筆記錄補上 `currencies` 欄位。

---

## 整體資料流程

```
FISC PDF
   ↓ pdfplumber 解析
atm_data.csv                    ← 唯一的 CSV（FISC 原始資料）
   ↓ 地理編碼（TGOS）
atm_geocoded.json               ← 主表（1,960 筆，含 lat/lng）
   ↑
   ├── skbank_currencies.json   ─┐
   ├── megabank_currencies.json  │  各銀行爬蟲輸出（JSON）
   ├── cathaybk_currencies.json  │  欄位：bank / branch / currencies
   ├── ctbc_currencies.json      ├─ merge_currencies.py
   ├── esunbank_currencies.json  │  子字串比對 join
   ├── hncb_currencies.json      │
   ├── sinopac_currencies.json   │
   ├── taishinbank_currencies.json │
   ├── bot_currencies.json       │
   └── firstbank_currencies.json ─┘
          ↓
atm_with_currencies.json        ← 最終完整表（前端讀這個）
```

Join 的鍵值不是固定欄位，而是字串比對：

```
FISC「銀行名稱」包含 bank_kw
AND
FISC「裝設地點」包含 branch
```

找不到對應的銀行則 `"currencies": null`，不從顯示結果中移除。

```json
{

  "denominations": {"USD": 100, "JPY": 10000, "CNY": 100, "HKD": 100}
}
```

## Merge 鍵值規則

### 主鍵：銀行代號 + 字串包含比對

FISC 的「裝設地點」通常是「{分行名}{編號}({備註})」格式，
例如：`世貿分行1(外幣提款機)`。

爬蟲的 `branch` 是官網顯示名稱，通常是乾淨的分行名，例如：`世貿分行`。

**比對邏輯**：
```
match = (fisc["銀行名稱"] 包含 scrape["bank"]) AND (fisc["裝設地點"] 包含 scrape["branch"])
```

新光銀行 POC 驗證：17/18（94%）可用此規則自動比對。

### 地址交叉驗證：方法與坑

#### 為什麼需要做

分行名稱比對（`branch ⊂ 裝設地點`）只確認「名字有對到」，不能確認「位置是對的」。
以下情況會讓名稱比對成功，但幣別實際掛錯地點：

| 坑 | 說明 | 後果 |
|----|------|------|
| 同名不同址 | 銀行改建/搬遷後官網更新，FISC 還未同步 | 幣別掛到舊地址的 ATM |
| 同名多台 | 「敦北分行」在 FISC 有 3 筆（不同機器），名稱比對全部命中 | 幣別套到不該套的機器 |
| 行外 ATM 名稱撞名 | 「桃園分行」可能對應到完全不同的 FISC 條目 | 幣別掛錯 |
| 地址格式不統一 | `9-1號` vs `9號之1`、`中山一路` vs `中山路一段` | 比對程式誤判為不吻合（假陽性） |

#### 驗證流程（反覆確認機制）

```
步驟 1：分行名稱比對，得出初步命中率
         ↓ 若有未命中 → 手動檢查名稱是否只是格式差異
步驟 2：地址交叉驗證（官網地址 vs FISC 地址）
         ↓ 若有不吻合 → 先看是否格式差異（漢字段別、區名前綴、-1 vs 之1）
         ↓ 若格式排除後仍不同 → 查是否多筆 FISC 條目（取任一吻合即通過）
         ↓ 若全部 FISC 條目都不同 → 真正地址差異，記錄 pending
步驟 3：改良正規化後重跑，確認「格式差異」和「真正不同」的分類正確
步驟 4：記錄結論，說明驗證覆蓋率（樣本數 / 總數）
```

#### 台灣地址常見格式差異（不算錯誤）

| 官網常見寫法 | FISC 常見寫法 | 實際是否同地 |
|------------|-------------|------------|
| `600-1號` | `600之1號` | ✓ 相同 |
| `中山一路` | `中山路一段` | ✓ 相同 |
| `東區光復路二段` | `光復路二段` | ✓ 相同（含/不含行政區）|
| `公道五路417-419號` | `公道五路417號` | ✓ 相同（地址範圍 vs 起始號）|
| `一段` | `1段` | ✓ 相同 |
| `臺北市` | `台北市` | ✓ 相同 |

#### 比對函數設計原則

單純比「前N字」容易因格式差異誤判。正確做法：

1. **先正規化**：`臺→台`、移除行政區詞（區/鎮/市）、統一段別（一段→1段）、移除園區前綴、`A-B號 → A之B號`
2. **取最寬鬆命中**：同分行有多筆 FISC 條目時，任一吻合即算通過
3. **人工複查殘餘**：正規化後仍不吻合的再逐筆看，確認是真錯還是沒處理到的格式

### 無法比對的情況

| 情況 | 原因 | 處理方式 |
|------|------|---------|
| 行外 ATM（商場、醫院等） | 官網不列行外機台，無對應 `branch` | `currencies: null`（不填，標未知） |
| 名稱完全不同 | 例如官網「天母傑仕堡」vs FISC 找不到 | 手動對應，或暫標 `currencies: null` |
| 一個 branch 對應多筆 FISC | 同分行放多台機器 | 所有台數套用同一組幣別 |

- **方式**：逐縣市 × 逐幣別查詢內部 JSON API（需 Referer header）
- **API（城市列表）**：`/ws/bank/atm/ws_ATM_GetCity.ashx`

**查詢策略**：  
先取得所有縣市清單，再對每縣市 × 每幣別（USD/JPY/CNY/HKD）各送一次 POST，以 `ATMCurr` 欄位過濾。

**幣別欄位對應**：  
回傳 JSON 中含 `WithdrawUSD`、`WithdrawJPY`、`WithdrawCNY`、`WithdrawHKD`，值為 `"1"` 表示支援。  
若欄位不存在或為空，則以查詢時的幣別 filter 補填（fallback）。

## 前端幣別篩選（Step 7）✅

**實作日期**：2026-05-09
**資料來源**：`index.html` 改為讀取 `atm_with_currencies.json`

### 篩選邏輯

- 預設不篩選（顯示全部）
- 選擇幣別 chip → **AND 邏輯**：選 USD + JPY → 只顯示同時有 USD **和** JPY 的 ATM
- 幣別為 `null`（尚未爬取的銀行）預設仍顯示，不因篩選而隱藏

**選 AND 不選 OR 的理由**：主要使用情境是「這次旅遊要提兩種幣，找一台能一次搞定的機器」。OR 邏輯選越多顯示越多，等同不篩選，沒有實際意義。

### UI

- 「銀行」filter sheet 頂部加幣別 chip 列（美元 USD / 日圓 JPY / 人民幣 CNY / 歐元 EUR / 港幣 HKD）
- Popup 點開後顯示該 ATM 支援的幣別標籤
