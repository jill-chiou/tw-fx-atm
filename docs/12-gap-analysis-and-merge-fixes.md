## 一、Gap 的定義

| 名稱 | 定義 |
|------|------|
| **Gap A** | FISC 有收錄，但 merge 失敗（currencies = null） |
| **Gap B** | 銀行官網有，但 FISC 沒有收錄的 ATM |

這兩種 gap 成因不同，處理方式也不同。

## 二、Gap B 分析（官網有、FISC 沒有）

### 為什麼要查 Gap B

FISC 每月更新一次，但實際上會有漏收的情況。
如果只以 FISC 為骨幹，就會漏掉這些機台。

### 分析方法

**錯誤的直覺**：拿「scraper 台數 − FISC 台數」的淨差值當作 Gap B 數量。

這是錯的，因為兩邊都可能有對方沒有的記錄：

```
┌─────────────────────────────────────────┐
│  FISC 91 筆（以永豐為例）                │
│  其中 74 筆 ↔ 有對應的 scraper 記錄      │
│  其中 17 筆 ↔ scraper 沒有這些分行       │  ← Gap A
└─────────────────────────────────────────┘

┌─────────────────────────────────────────┐
│  Scraper 95 筆                          │
│  其中 79 筆 ↔ 有對應的 FISC 記錄         │
│  其中 16 筆 ↔ FISC 完全沒有             │  ← Gap B
└─────────────────────────────────────────┘

淨差 95 − 91 = +4 ≠ 16（Gap B 實際數量）
```

**正確方法**：對每筆 scraper 記錄，反向查 FISC。
比對規則：地址正規化比對 + 分行名稱子字串比對，兩者都找不到才算 Gap B。

### 地址正規化的重要性

第一次跑出 67 筆「不匹配」，遠多於預期。
原因是大量 A 類問題（同一台機器、地址格式不同）：

| 官網地址 | FISC 地址 | 問題 |
|---------|---------|------|
| `德惠街16之5號` | `德惠街16號之5` | `之` 的位置不同 |
| `博愛路17 號` | `博愛路17號` | 多一個空格 |
| `化成路540之1號` | `化成路540號之1` | 同上 |
| `新竹縣...自強南路25、27號1...樓` | `自強南路25號` | 多門牌 / 樓層 |

加強正規化後（處理上述格式差異），縮減至真正的 22 筆 Gap B。

### Gap B 最終結果

| 銀行 | 筆數 | 說明 |
|------|------|------|
| 永豐 | 16 | 各分行（sinopac API 逐縣市查詢有漏）|
| 玉山 | 5 | 各分行（HTML 爬取有漏）|
| 國泰世華 | 1 | 全家\_葵爾特店（超商型 ATM）|
| **合計** | **22** | 全部有 lat/lng，可直接補入 |

**為什麼只查這 3 家？**
只有 scraper 台數 > FISC 台數的銀行才可能有 Gap B。
其他家（台新、兆豐等）FISC 台數反而更多，無 Gap B 可查。

### 實作方式（`merge_currencies.py`）

在 merge 最後加入 `find_gap_b()` 函式：
1. 對 3 家銀行的 scraper 資料，逐筆做反向 FISC 比對
2. 比對不到的記錄以 `source="bank_website"` 追加進輸出
3. FISC 原有記錄加上 `source="fisc"`

**為什麼加 `source` 欄位？**
方便之後 SQLite pipeline 追蹤資料來源，也讓前端可以選擇性呈現。

## 三、Gap A 修正（FISC 有、merge 失敗）

### 原始 45 筆 null 的根本原因

#### 類型 1：Merge 邏輯 bug（4 筆）

**上海商業儲蓄銀行（2 筆）— bank_kw 提取錯誤**

merge 腳本用以下邏輯萃取銀行關鍵字：
```python
bank_kw = bank.replace("銀行", "").replace("國際商業", "").replace("商業", "")
```
`上海商業儲蓄銀行` 經過這個流程後變成 `上海儲蓄`。
但 `"上海儲蓄" in "上海商業儲蓄銀行"` → **False**，導致比對永遠失敗。

修正：加上 `.replace("儲蓄", "")`，讓關鍵字變成 `上海`，就能正確比對。

**玉山「第二總部大樓」+ 永豐「南山人壽」（各 1 筆）— substring 方向問題**

原邏輯只查單方向：scraper branch 是否在 FISC 裝設地點裡。
```
scraper: 玉山銀行第二總部大樓   ←（較長）
FISC:    第二總部大樓           ←（較短）
"玉山銀行第二總部大樓" in "第二總部大樓" → False
```
反向才是對的：`"第二總部大樓" in "玉山銀行第二總部大樓"` → True

修正：改為雙向比對
```python
if branch_or_fisc in fisc_loc or fisc_loc in branch_or_fisc:
```

#### 類型 2：Scraper 沒有這筆資料（41 筆）

這些是 FISC 有收錄、但各家爬蟲沒有抓回來的 ATM。
依銀行和原因分類：

| 銀行 | 筆數 | 原因 | 處理方式 |
|------|------|------|---------|
| 新光 | 12 | 官網 HTML 只列分行型機台，商場/醫院型未列 | Fallback（同銀行標準幣別）|
| 兆豐 | 8 | 機場幾個 hall API 未回傳 | Fallback（機場標準幣別）|
| 玉山 | 2 | 醫院/大樓型 ATM HTML 未列 | Fallback（同銀行標準幣別）|
| 華南 | 1 | 溪湖分行 XML 未回傳 | Fallback（同銀行標準幣別）|
| 永豐 | 15 | sinopac API 逐縣市/幣別查詢有漏 | 手動查官網確認（見下）|
| 第一商銀 | 2 | 官網無此機台 | 排除 |
| 永豐 | 1 | 不對外服務 | 排除 |

**為什麼用 fallback 而不是重爬？**
這些機台的問題是爬蟲覆蓋範圍不足，不是資料錯誤。
重爬需要確認能抓到這些特殊場所，成本高。
FISC 已確認這些都是外幣 ATM，套用該銀行已知的最小幣別集合是合理的保守估計。

### FALLBACK_CURRENCIES 設計原則

只有滿足以下條件才放進 fallback：
1. FISC 資料確認這些是外幣 ATM（非 FISC 的記錄不在考慮範圍）
2. 官網明確說明該銀行的最小支援幣別
3. 爬蟲已確認同銀行的大部分機台都支援這組幣別

```python
FALLBACK_CURRENCIES = {
    "台新": ["CNY", "EUR", "JPY", "USD"],  # ATM 服務頁明確說明
    "兆豐": ["CNY", "EUR", "HKD", "JPY", "USD"],  # 機場 ATM 標準
    "新光": ["CNY", "HKD", "JPY", "USD"],
    "玉山": ["CNY", "HKD", "JPY", "USD"],
    "華南": ["CNY", "HKD", "JPY", "USD"],
}
```

### FISC_EXCLUDE 設計原則

從輸出中完全排除，不留 null 也不留 fallback。
條件：官網查無此機台，或明確標示不對外服務。

```python
FISC_EXCLUDE = {
    ("永豐", "南山人壽-民權(不對外)"),   # 不對外
    ("第一", "中華航空公司組派大樓2F"),   # 官網查無
    ("第一", "金湖停車場"),              # 官網查無
    ("永豐", "世貿分行"),               # 官網確認無外幣
    ("永豐", "三民分行"),               # 同上
    ("永豐", "岡山分行"),               # 同上
    ("永豐", "忠孝東路分行"),            # 同上
    ("永豐", "萬華分行"),               # 同上
    ("永豐", "興隆分行"),               # 同上
    ("永豐", "中山分行"),               # 同上
    ("永豐", "鶯歌分行"),               # 同上
}
```

scraper API 沒有回傳這些分行，逐一去永豐官網查詢後確認：

**有外幣提款（補進 `sinopac_currencies.json`）：**

| 分行 | 幣別 |
|------|------|
| 敦南分行 | JPY, USD |

| 成大分行 | JPY, USD |

## 六、`merge_currencies.py` 架構

```
FISC atm_geocoded.json（1,960 筆）
  │
  ├─ 排除 FISC_EXCLUDE（11 筆非公開）
  │
  ├─ build_lookup()
  │    從所有 scraper JSON 建立 (bank_kw, branch) → currencies 的查找表
  │
  ├─ 主迴圈（逐筆 FISC 記錄）
  │    1. branch 子字串雙向比對（精確配對）
  │    2. FALLBACK_CURRENCIES 兜底
  │    3. 加上 source="fisc"
  │
  └─ find_gap_b()
       反向查：scraper 有但 FISC 沒有的記錄
       加上 source="bank_website" 追加到輸出末尾
       （只查 國泰世華 / 玉山 / 永豐 這 3 家）

輸出：atm_with_currencies.json（1,971 筆，100% 有幣別）
```
